# Публикация и запуск

## Самое важное: какой файл открывать

В проекте **два файла с одинаковым именем `index.html`**:

| Путь | Что это | Работает в браузере |
|---|---|---|
| `index.html` (в корне) | исходный код для сборки | ❌ нет — белый экран |
| `docs/index.html` | **готовое приложение** | ✅ да |
| `dist/index.html` | тоже готовое приложение (результат сборки) | ✅ да |

Открытие корневого `index.html` или публикация корня репозитория даёт ровно белый
экран: браузер встречает там TypeScript и не может его выполнить.

**Открывайте и публикуйте `docs/index.html`.** Он уже собран — никаких команд
выполнять не нужно.

---

## Куда вводить команды `npm install` / `npm run build`

**Не на сайт GitHub**, а на своём компьютере, в программе для командной строки:

- **Windows:** откройте папку проекта в Проводнике → правый клик по пустому месту →
  «Открыть в терминале» (или «Open in Terminal» / PowerShell). Затем вводите команды
  и нажимайте Enter.
- **macOS:** Программы → Утилиты → Терминал, затем наберите `cd ` (с пробелом),
  перетащите в окно папку проекта и нажмите Enter.

Для команд нужен установленный [Node.js](https://nodejs.org) версии 20+.

> Но для публикации на GitHub эти команды **не нужны** — см. способ 1 ниже.

## Способ 1. GitHub Pages из папки `docs` — БЕЗ сборки и без Actions ✅

Рекомендуемый путь. Не требует Node.js, npm, терминала и GitHub Actions.

1. Убедитесь, что в репозитории загружена **папка `docs`** с файлом `index.html`.
2. Откройте репозиторий → **Settings → Pages**.
3. **Build and deployment → Source:** выберите `Deploy from a branch`.
4. **Branch:** `main`  **Folder:** `/docs` → нажмите **Save**.
5. Через 1–2 минуты приложение доступно:
   `https://ЛОГИН.github.io/ИМЯ_РЕПО/`

Готово. Никаких сборок — GitHub просто отдаёт готовый файл.

### Если после этого белый экран
Значит, опубликовалась папка `/ (root)`, а не `/docs`, либо папка `docs` вообще не
загрузилась в репозиторий. Проверить просто: откройте в браузере адрес
`https://ЛОГИН.github.io/ИМЯ_РЕПО/` и посмотрите, что выдаёт приложение — при
неполадке на экране появится красная плашка с точным объяснением и адресом файла.

> Частая проблема: при загрузке файлов через веб-интерфейс GitHub папка `docs`
> не загружается. После загрузки откройте репозиторий и убедитесь глазами, что
> папка `docs` видна в списке файлов.

## Способ 2. GitHub Actions — автосборка при каждом пуше

В проекте есть `.github/workflows/deploy.yml`.

1. Загрузите весь проект (включая скрытую папку `.github`).
2. **Settings → Pages → Source:** `GitHub Actions`.
3. Вкладка **Actions** → дождитесь зелёной галочки «Deploy to GitHub Pages».

Способ удобен, если вы правите исходники. Если Actions падает — используйте
способ 1, он надёжнее.

## Способ 3. Вообще без хостинга

В работающем приложении нажмите **«📦 Офлайн-копия»** — скачается один файл
`066у-приложение.html` с целой программой внутри. Открывается двойным щелчком,
работает без интернета, переносится на флешке.

---

## Способ 4. Netlify Drop — 2 минуты

1. Скачайте репозиторий ZIP, распакуйте.
2. Откройте https://app.netlify.com/drop
3. Перетащите **папку `docs`** в окно браузера.

Получите адрес вида `https://имя.netlify.app`. Регистрация на старте не нужна.

## Прочие площадки

| Площадка | Что загрузить |
|---|---|
| Cloudflare Pages (`*.pages.dev`) | папку `docs`, build можно не указывать |
| Vercel (`*.vercel.app`) | репозиторий, output `dist` |
| GitLab Pages (`*.gitlab.io`) | содержимое `docs` |
| Российский хостинг (Beget, Timeweb, reg.ru) | `docs/index.html` в корень сайта по FTP |
| Yandex Cloud Object Storage | `docs/index.html` в бакет-сайт |

Для любого обычного хостинга действие одно: положить `docs/index.html` в корень.

## Диагностика

Приложение спроектировано так, чтобы не молчать:

- **Пустой экран с красной плашкой** — прочитайте текст на ней: там указана причина
  и открытый адрес. Это главный источник ответов.
- **Плашка «Приложение не запустилось»** — опубликован исходный файл. Настройте
  Pages на папку `/docs` (способ 1).
- **Ошибка во время работы** — появится окно с описанием и кнопками
  «Перезагрузить» / «Сбросить данные».
- **localStorage запрещён** политикой браузера — приложение работает, но без
  автосохранения; для переноса данных используйте «💾 JSON» → «📂 Открыть».
- **Старый браузер** (Chrome до 88, Firefox до 78, Safari до 14) — нужен современный
  браузер, на служебных компьютерах это частая причина.
- **Печать выдаёт не 2 страницы** — в диалоге печати масштаб 100%, поля по умолчанию,
  снять «Верхние и нижние колонтитулы».

## Обновление приложения после правок исходников

Если вы меняли код, пересоберите и обновите копию в `docs`:

```
npm install
npm run build
cp dist/index.html docs/index.html
```

Затем загрузите новый `docs/index.html` в репозиторий.

---

## Безопасность данных

Приложение не отправляет данные никуда: нет аналитики, телеметрии, внешних шрифтов
и CDN-запросов. Всё, что вы вводите (ФИО пациентов, диагнозы, СНИЛС), остаётся
в браузере на этом компьютере. Поэтому оно работает и за корпоративным файрволом.
