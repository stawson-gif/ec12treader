# Публикация и запуск: полная инструкция

## ⚠️ Если вы видите белый экран — прочитайте это первым

В проекте **два файла с одним и тем же именем `index.html`**, и это главная причина
белого экрана:

| Файл | Что это | Работает в браузере? |
|---|---|---|
| `index.html` (в корне проекта) | **исходный код** для сборки | ❌ никогда |
| `dist/index.html` (после сборки) | **готовое приложение** | ✅ да |

Открытие корневого `index.html` двойным щелчком или загрузка корня репозитория на
хостинг даёт ровно белый экран — потому что браузер встречает строку
`<script type="module" src="/src/main.tsx">` и не может выполнить TypeScript.

### Что делать

```
npm install
npm run build
```

После этого появится папка **`dist`** с одним файлом `index.html` (~500 КБ).
**Только его** нужно открывать и загружать на хостинг.

---

## 1. Локальный запуск

### Вариант А. Просто открыть файл
```
npm install
npm run build
```
Затем двойной щелчок по **`dist/index.html`**. Приложение полностью работает,
интернет не нужен.

> Браузер спросит разрешение на локальное хранилище — разрешите, это автосохранение.

### Вариант Б. Через локальный сервер (если вариант А не сработал)
Некоторые корпоративные политики запрещают скрипты для `file://`. Тогда:
```
npx serve dist
```
и откройте показанный адрес, например `http://localhost:3000`.

### Проверка, что вы открыли правильный файл
Внутри правильного файла в самом начале есть строка
`<div id="root">` и далее **один огромный блок кода**, а ссылки вида
`/src/main.tsx` — **отсутствуют**. Файл весит около 500 КБ. Исходный — 1 КБ.

## 2. GitHub Pages

Приложение уже содержит готовый workflow `.github/workflows/deploy.yml`.

### Правильный путь (рекомендуется)
1. Залейте **исходники проекта** в репозиторий (папки `src`, файлы `package.json`,
   `vite.config.ts`, `index.html` и остальные — **весь репозиторий целиком**,
   включая `.github`).
2. В репозитории: **Settings → Pages → Build and deployment → Source** →
   выберите **GitHub Actions**.
   ⚠️ Это ключевой шаг. Если оставить «Deploy from a branch», GitHub опубликует
   корень репозитория — то есть исходный `index.html`, и будет белый экран.
3. Вкладка **Actions** → дождитесь зелёной галочки «Deploy to GitHub Pages».
4. Адрес: `https://ЛОГИН.github.io/ИМЯ_РЕПО/`

При таком способе ничего собирать вручную не нужно — GitHub сам запускает
`npm run build` и публикует папку `dist`.

### Альтернатива: без Actions
Если хотите публиковать вручную — загрузите **содержимое папки `dist`** (сам файл
`index.html`) в корень репозитория, а в **Settings → Pages → Source** выберите
«Deploy from a branch» → ветка `main`, папка `/ (root)`.

Типичная ошибка: загрузить папку `dist` целиком как подпапку. Тогда адрес будет
`.../dist/index.html`, а корень останется пустым. Загружайте именно **содержимое**.

## 3. Netlify Drop — за 2 минуты, без регистрации

```
npm install
npm run build
```
1. Откройте https://app.netlify.com/drop
2. Перетащите **папку `dist`** в окно.
3. Получите адрес `https://случайное-имя.netlify.app`.

В проекте есть `netlify.toml`, поэтому при подключении репозитория всё соберётся само
(command: `npm run build`, publish: `dist`).

## 4. Другие площадки

| Площадка | Домен | Настройки |
|---|---|---|
| Cloudflare Pages | `*.pages.dev` | build `npm run build`, output `dist` |
| Vercel | `*.vercel.app` | импорт репозитория, настройки определяются сами |
| GitLab Pages | `*.gitlab.io` | артефакт — папка `dist` |
| Российский хостинг (Beget, Timeweb, reg.ru) | ваш домен `.ru` | загрузить `dist/index.html` в корень по FTP |
| Yandex Cloud Object Storage | домен Яндекса | бакет как статический сайт, файл `index.html` |

Для любого обычного хостинга действие одно: **положить `dist/index.html` в корень сайта**.

## 5. Диагностика проблем

Приложение спроектировано так, чтобы **не молчать**:

- Если код не смог запуститься — вместо белого экрана появляется красная плашка
  с конкретной причиной и адресом открытого файла.
- Если ошибка возникла во время работы — показывается окно с описанием и кнопками
  «Перезагрузить» / «Сбросить данные».
- Если localStorage недоступен (запрещён политикой браузера) — приложение
  продолжает работать, просто без автосохранения.

### Белый экран, ничего не появляется
1. Проверьте, что открыт `dist/index.html`, а не корневой `index.html`.
2. Обновите браузер: нужен Chrome/Edge 88+, Firefox 78+, Safari 14+.
   На старых браузерах (например, Chrome 60 на служебном ПК) современный код
   не выполняется — поставьте актуальный браузер.
3. Откройте консоль разработчика (**F12 → Console**) — там будет точный текст ошибки.

### Печать выдаёт не 2 страницы
В диалоге печати: масштаб **100%**, поля **по умолчанию**, снимите галочку
«Верхние и нижние колонтитулы».

### Данные не переносятся на другой компьютер
Данные хранятся в браузере того компьютера, где велся ввод. Перенос:
кнопка **«💾 JSON»** на первом компьютере → **«📂 Открыть»** на втором.

### Нужен доступ с планшета / компьютера без интернета
Кнопка **«📦 Офлайн-копия»** сохраняет всё приложение одним файлом. Перенесите его
на флешке или по сети и открывайте локально.

## 6. Безопасность данных

Приложение **не отправляет данные никуда**: нет аналитики, телеметрии, внешних
шрифтов и CDN-запросов. Всё, что вы вводите (ФИО пациентов, диагнозы, СНИЛС),
остаётся в браузере на этом компьютере. Поэтому оно работает и за корпоративным
файрволом.
